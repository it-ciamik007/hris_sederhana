# HRIS Fase 1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Membangun self-service karyawan (`/my/*`), CRUD master data organisasi, dan notifikasi in-app sesuai spec `docs/superpowers/specs/2026-06-10-hris-phase1-design.md`.

**Architecture:** Mengikuti pola project: page = server component yang query Prisma langsung; mutasi = HTML form POST ke API route lalu redirect; logika bisnis di `src/server/services/*`; komponen client hanya untuk interaksi. Verifikasi per task: `npx tsc --noEmit` (project belum punya test runner — ditunda ke fase hardening sesuai spec).

**Tech Stack:** Next.js 15 App Router, Prisma 6 + MySQL, Tailwind, zod, jose.

**Konvensi penting:**
- Migrasi DB manual bernomor: `prisma/migrations/000N_nama/migration.sql` (lihat 0006).
- Auth: `getSession()` dari `src/lib/auth.ts` → `SessionUser { id, employeeId?, roles, permissions }`.
- Permission API/page via prefix di `src/lib/route-permissions.ts` (dicek middleware).
- Approve/reject memakai `approveStep(approvalRequestId, stepId, userId?, note?)` / `rejectStep(...)` dari `src/server/services/approval.service.ts`.
- Styling halaman baru pakai design token (`bg-card`, `text-muted-foreground`, `border-border`), bukan `bg-white` hardcoded. Mobile-first: card list di `< md`, tabel di `md+`.

- [ ] **Step 1: Tambah model Prisma**

```prisma
model Notification {
  id        String    @id @default(dbgenerated("(UUID())")) @db.Char(36)
  userId    String    @map("user_id") @db.Char(36)
  title     String    @db.VarChar(200)
  body      String    @db.Text
  link      String?   @db.VarChar(500)
  readAt    DateTime? @map("read_at") @db.DateTime(0)
  createdAt DateTime  @default(now()) @map("created_at") @db.DateTime(0)

  user User @relation(fields: [userId], references: [id])

  @@index([userId, readAt], map: "idx_notifications_user_read")
  @@map("notifications")
}
```
Plus `notifications Notification[]` di model `User`.

- [ ] **Step 2: Migration SQL**

```sql
CREATE TABLE notifications (
  id CHAR(36) NOT NULL DEFAULT (UUID()),
  user_id CHAR(36) NOT NULL,
  title VARCHAR(200) NOT NULL,
  body TEXT NOT NULL,
  link VARCHAR(500) NULL,
  read_at DATETIME NULL,
  created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  PRIMARY KEY (id),
  KEY idx_notifications_user_read (user_id, read_at),
  CONSTRAINT fk_notifications_user FOREIGN KEY (user_id) REFERENCES users(id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

Jalankan: `npx prisma migrate deploy` (atau `db push` bila dev DB belum sinkron) lalu `npx prisma generate`.

- [ ] **Step 3: Service**

`notification-inapp.service.ts` mengekspor:
- `notifyUser(input: { userId: string; title: string; body: string; link?: string })` → `db.notification.create`.
- `notifyEmployee(input: { employeeId: string; title: string; body: string; link?: string })` → cari semua `user` aktif dengan `employeeId` tsb, buat notifikasi per user; abaikan diam-diam bila tak ada user.
- `notifyRole(input: { roleCode: string; title: string; body: string; link?: string })` → semua user aktif ber-role tsb.
